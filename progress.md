- **Smart App Control на рабочей машине владельца блокирует нативный `satteri`** (Markdown-процессор Astro 7, `@astrojs/markdown-satteri`): `An Application Control policy has blocked this file … satteri_napi.win32-x64-msvc.node`. Остальные нативные модули (rolldown, sharp, lightningcss, компилятор Astro) грузятся. Обход — только локальный: после каждого `npm ci` / `npm install` (включая `npm install -D <пакет>`: он тоже удаляет обход, ep01 T04) выполнить `npm install --no-save --force @bruits/satteri-wasm32-wasi@<версия satteri из npm ls satteri>`. Загрузчик satteri сам падает на WASI-сборку, если нативная не загрузилась. `package.json` и `package-lock.json` не меняются, в CI (Linux) грузится нативная сборка. Симптом без обхода: `astro check` / `vitest` / `astro build` падают с `Cannot find native binding`. (ep01 T02)
- **В Windows-окружении нет `python`** — скриптовые правки файлов делаются через `node`. (ep01 T01)
- **`tsconfig.json` исключает `docs`**: иначе `astro check` проверяет JS дизайн-источников в `docs/inputs/` и шумит подсказками. (ep01 T02)
- **Две ступени токенов**: примитивы ДС — `src/styles/tokens/*.css` (копия без изменений, тест `contrast.test.ts` сверяет со снимком `tests/fixtures/ds-sources.json`, снимок с `docs/inputs/…` — `ds-sources.test.ts`); семантика — только `src/styles/theme.css`. Имена семантики не повторяют имена примитивов (`--radius-sm` занят ДС → `--radius-field`; `--space-1…9` → `--space-2xs…2xl`), иначе `var()` зацикливается. Компоненты используют только семантику. (ep01 T03)

- **Схемы с `image()` и `reference()` — фабрики** в `src/lib/schemas.ts` (`pageSchema(image, reference)`, `blockSchema(reference)`, `siteSchema(image)`); `content.config.ts` передаёт настоящие функции, тесты — `() => z.string()`. `astro:*` в `schemas.ts` не импортируется. Refine навешивается внутри фабрики последним шагом: Zod 4 бросает ошибку на `.extend()` у схемы с refine, а `.safeExtend()` унёс бы поля и их default в `content.config.ts`, вне тестов схем. `.extend` снаружи — только у схем без refine (`caseSchema`). Лимиты длин — в `LIMITS`, тест границы — `expectLimit` (ровно по лимиту проходит, +1 — ошибка по пути). (ep01 T06, ep02 T06)
- **Видимая высота знака — токен, `size` у `Logo` — разрешение растра.** Предок задаёт `--logo-height: var(--logo-…-h)` (токены в `theme.css`), `Logo.astro` берёт её, иначе высоту растра (`--logo-size`). `size` должен быть не меньше максимума токена, иначе знак растягивается. Так lockup заглушки ужимается до 360px без горизонтального скролла. (ep01 T08)

- **Два репозитория в одной рабочей папке** (с 2026-09-24): корень — публичный код `belka-site`, `docs/` — отдельный git приватного `belka-site-docs` (корень игнорирует `docs/`). Задание, пропущенное из-за упавшего `needs`, GitHub засчитывает required check как успех. Новый гейт добавляется в `needs`, имя проверки не меняется. - **Скрипты-проверки для workflow — в `infra/<назначение>/*.sh`**, а не шагами YAML: их прогоняют локально (Git Bash) и проверяет shellcheck в `gates.yml` (новый исполняемый файл `infra/`, в том числе без `.sh`, как `belka-deploy`, — в список шага «shellcheck скриптов infra»). - **Доставка — `deploy.yml` + `rollback.yml`, клиент сервера — `infra/deploy/ci-deploy.sh`, смоук — `infra/deploy/smoke.sh`.** Выкладывается artifact из прогона `gates` того же workflow; выкладка и смоук — шаги одного job с `environment:` (`concurrency: deploy-<env>` у обоих workflow). Промоушн вызывает `gates` с `site_env: staging` и `ref: <sha>` — те же гейты, что у стейджинга, плюс staging-`draft-routes.json` для проверки 404 черновиков на проде. Проверка «SHA на стейджинге» — успешный deployment `staging` (статус `success` ищется в истории: после следующей выкладки он становится `inactive`) **и** успешный push-прогон `deploy.yml`: `rollback.yml` тоже создаёт deployment, но с SHA запуска. Reusable `gates.yml` и `infra/deploy` в прогоне промоушна берутся из HEAD `main`, а не из SHA, поэтому SHA ≠ HEAD промоутится, только если между ними не менялись `.github/` и `infra/deploy/` (`infra/deploy/promote-guard.sh` по compare API, /my-verify ep01, F01 Codex). Смоук знает только инварианты окружения; с `--dist` тело `/` и 404 сверяется побайтно со сборкой. (ep01 T17, T18)

- **Пограничная проба гейта**: у каждого гейта есть проба не только на грубую поломку, но и на границу заявленного: агрегация (медиана, а не лучший прогон), охват правила (все свойства, которые обещает принцип), состояние, на котором гейт должен отказать (промоушн SHA ≠ HEAD). Проба — регресс-тест, который падает на мутанте с прежним поведением. Негативы T24 доказали только грубые случаи, а медиану Lighthouse, охват Stylelint и `promote-guard` нашёл `/my-verify`. - **Инструмент записи файлов Claude превращает escape-последовательности `\uXXXX` в сырые символы** — не только U+2028/U+2029, а любые (ep02 T02: `\u00A0`, `\u2009`, `\u202F`, `\uFFFC` в регулярках и строках стали невидимыми символами). - **Линтер голоса — `scripts/check-voice.mjs`** (`parse5`): проверяет форму видимого текста собранного HTML (V1–V10) и `--text` — блоки ```` ```text ```` пакета черновиков (одна строка — один абзац). Текст собирается по блокам: строчные элементы (`INLINE`) склеиваются, всё остальное — граница; `script`, `style`, `code`, `pre`, `template`, `noscript`, `hidden` пропускаются; атрибуты `alt`, `aria-label`, `title`, `description`, текстовые `og:*` и строки JSON-LD (кроме служебных ключей `@type`, `url`, `logo`, контактов; невалидный JSON — нарушение, ep02 T19) — отдельные блоки. Исключение — только `data-voice="raw"` в разметке, снимает V3, V4, V10. Границы слов для кириллицы — `(?<![\p{L}\p{N}])…(?![\p{L}\p{N}])` с флагом `u`: `\b` в JS кириллицу не видит. Флаг `i` вместе с `\p{Lu}` в JS совпадает и со строчными, поэтому регистр в V7 задаётся явно (`[Бб]`). Каждая граница правила держится тестом, проверено 44 мутантами. Смысл, факты и приватный чек-лист в код не попадают (Constitution 10). (ep02 T02)
- **Гейт адаптива — `scripts/check-layout.mjs`** (`playwright-core` + системный Chrome, `chromium.launch({ channel: 'chrome' })`, браузер не скачивается): все `**/*.html` сборки на 360 / 768 / 1440 × 800 через встроенный сервер `startStaticServer(root)` из `scripts/lib/static-server.mjs` (`node:http`, `127.0.0.1`, свободный порт, `..` и выход из корня → 404, неизвестное → `404.html` с кодом 404; его же берёт OG-рендер T13). Headless Chrome скрывает скроллбары (`innerWidth` = `clientWidth`), у строчных элементов `scrollWidth`/`clientWidth` = 0. Тест с Chrome: без Chrome он падает, `skipIf` нет; таймаут 120 с на `beforeAll` и блок CLI (запуск CLI с импортом `playwright-core` — ~1 с). На Windows `EPERM` при закрытии, как у LHCI, нет. Фикстуры-пробы — `tests/fixtures/layout/`; «проходящая» фикстура не должна давать реальный скролл (элемент `visibility: hidden` шириной 900px его даёт). (ep02 T03)
